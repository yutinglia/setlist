# Test coverage policy

Coverage is a required quality gate for both application stacks. A pull request
or `main` push cannot pass CI when either stack is below its threshold, and a
release cannot publish unless the tagged commit already has a successful
coverage-gated CI run.

## Thresholds

| Stack | Measured metrics | Required minimum |
| --- | --- | --- |
| Backend | Coverage.py combined statements and branches | 80% |
| Frontend | Statements, branches, functions, and lines | 80% each |

The gate is intentionally per stack. High backend coverage cannot hide an
untested frontend, or vice versa.

## Measured source

Backend coverage starts from every Python source file under `backend/`,
including the API, application services, repositories, scraper adapters,
configuration, and maintenance entry points. It excludes:

- `backend/tests/`, because test code is not product coverage;
- `backend/db/models.py`, because Flyway is the schema source and this ORM file
  is generated by `sqlacodegen`;
- `backend/services/yt_scraper/test.py`, because it is an operator-run live
  YouTube smoke script rather than an automated test target;
- `if __name__ == "__main__"` launch guards, type-check-only blocks, and
  deliberate abstract `NotImplementedError` statements.

Frontend coverage starts from every TypeScript and TSX file under
`frontend/src/`, including routes, components, hooks, stores, and the browser
entry point. It excludes only tests/test helpers, ambient declarations, and
generated Paraglide/TanStack Router output.

## Local analysis

Start and migrate PostgreSQL before the complete backend run:

```bash
docker compose -f docker-compose.dev.yml up -d db
docker compose -f docker-compose.dev.yml run --rm flyway

cd backend
python -m pip install -r requirements-dev.txt
python -m pytest \
  --cov \
  --cov-report=term-missing:skip-covered \
  --cov-report=xml:coverage.xml \
  --cov-report=html:htmlcov
```

Open `backend/htmlcov/index.html` for file and branch details. The XML report is
suited to editor and CI tooling. A focused `python -m pytest path/to/test.py`
remains available without forcing a whole-project coverage gate.

Run frontend coverage separately:

```bash
cd frontend
npm ci
npm run test:coverage
```

Open `frontend/coverage/index.html` for line and branch details. The same
directory contains `coverage-summary.json` and LCOV output for automation.
Plain `npm test` remains the fast test-only command.

Critical browser flows use Playwright with deterministic API stubs, so they
exercise the built application in Chromium without depending on PostgreSQL or
live YouTube access:

```bash
cd frontend
npx playwright install chromium
npm run test:e2e
```

The E2E suite intentionally covers only high-value journeys: public song
search and detail navigation, timestamped video setlists, and the administrator
authentication boundary. Component variants and edge cases stay in Vitest,
where they are faster and easier to diagnose.

## CI and release behavior

The backend and frontend CI jobs generate readable terminal summaries and
upload their full reports as `backend-coverage` and `frontend-coverage`
artifacts for 14 days. Each job also writes its totals to the GitHub Actions run
summary, so reviewers can see the gate result without downloading an artifact.
Coverage failures stop their job before production image builds. The frontend
job also installs Chromium and runs Playwright, retaining failure screenshots,
video, traces, and the HTML report as an artifact. The release workflow also
queries GitHub Actions for a successful CI run on the exact tagged commit before
building or publishing images.

Coverage is a guardrail, not a substitute for assertions. New tests should
exercise observable behavior, errors, and boundary conditions; avoid imports or
mock-only execution whose sole purpose is inflating a percentage.
